# Nanobug 初版插件市场执行规格

日期：2026-10-09。稳定标识：`plugin-marketplace-v1`。
状态：产品范围、主要测试接缝、四张粗粒度工单和四条直接阻塞边已于 2026-10-09 获用户确认；执行规格已发布为 [#1](https://github.com/T-miracle/Nanobug-Plugin-Marketplace/issues/1)，四张工单已发布并核对阻塞关系，尚未开始实现。
目标跟踪器：T-miracle/Nanobug-Plugin-Marketplace GitHub Issues；发布标签：`ready-for-agent`。发布前检索稳定标识，避免重复创建。

## Problem Statement

用户当前从本机插件包获得能力，不能在 Nanobug 中获取经过统一审核的第三方插件目录、比较历史版本、查看下载次数，并安装适合当前宿主的版本。已有插件详情里的版本与更新日志入口不能仅凭本地随附目录提供完整信息，用户也缺少无需打开管理器即可看到的更新提示。

官方插件随编辑器分发且源码集中在主仓库，独立发布和升级边界不够明确。第三方作者需要一个清楚的提交、审核、身份归属和版本不可变规则，维护者需要在不建设额外后端的情况下管理这些发布。

## Solution

提供编辑器内的原生插件市场，包含列表、搜索、分类、详情、下载、下载次数、历史版本、更新日志及指定兼容版本安装。GitHub Pages 只托管静态目录与统计数据；插件包保存在作者的 GitHub Releases；GitHub Actions 校验提交、生成索引并定期汇总统计。

第三方通过 PR 向官方注册表提交插件仓库、源码 commit、许可证及 Release 附件地址。首次收录和每个新版本均经自动校验与人工审核。仅收录开源稳定版。默认安装最高兼容版本，已有插件只能从市场升级。首次安装确认权限，升级新增权限再次确认，失败保护旧插件和数据。

启动后及运行期间后台检查更新，有可安装更新时在插件按钮显示红点，由用户触发更新。最新列表刷新失败时可浏览缓存，但不能从市场新装或升级；已安装插件和本地 ZIP 导入继续使用。

七个正式插件迁到各自独立仓库，停止随附分发。全新安装保留纯文本编辑、内置终端和默认主题；用户自行打开市场取得插件能力。移除示例源码前，将相关测试迁至专用夹具并保留覆盖。

## User Stories

1. As an 编辑器用户, I want 在原生插件管理器中浏览市场, so that 在编辑器内完成发现与安装。
2. As an 编辑器用户, I want 搜索名称、插件 ID、简介、作者和标签, so that 找到需要的插件。
3. As an 编辑器用户, I want 按主分类筛选并查看标签, so that 理解插件的主要用途。
4. As an 编辑器用户, I want 无搜索词时默认按下载次数排序, so that 查看已有使用记录的插件。
5. As an 编辑器用户, I want 有搜索词时默认按相关性排序, so that 优先看到匹配结果。
6. As an 编辑器用户, I want 切换相关性、下载次数、最近更新与名称排序, so that 按当前需要比较插件。
7. As an 编辑器用户, I want 查看名称、图标、简介、作者及说明正文, so that 判断插件是否适合自己。
8. As an 编辑器用户, I want 查看许可证、源码仓库与问题反馈链接, so that 了解使用条件并联系维护者。
9. As an 编辑器用户, I want 查看版本、发布时间、兼容条件与权限, so that 理解安装影响。
10. As an 编辑器用户, I want 浏览详情时无需下载完整插件包, so that 更快比较候选插件。
11. As an 编辑器用户, I want 使用中英文界面并在插件内容缺少译文时看到原文, so that 仍能获取完整信息。
12. As an 编辑器用户, I want 查看插件累计与各版本下载次数及统计时间, so that 正确理解统计的时效与口径。
13. As an 编辑器用户, I want 统计失败时看到旧值或暂不可用而非虚假的零, so that 不误解插件使用情况。
14. As an 编辑器用户, I want 查看所有已收录版本及各自更新日志, so that 比较版本变化。
15. As an 编辑器用户, I want 默认选择当前宿主与平台可用的最高稳定版本, so that 避免安装无法运行的最新版本。
16. As an 编辑器用户, I want 首次安装时可选择旧的兼容版本, so that 按需要使用历史版本。
17. As an 编辑器用户, I want 不兼容版本显示原因且不能安装, so that 避免无效操作。
18. As an 编辑器用户, I want 已安装插件的市场操作仅允许升级, so that 避免误触降级或同版本重装。
19. As an 编辑器用户, I want 首次下载前确认权限, so that 自己决定是否安装。
20. As an 编辑器用户, I want 升级新增权限时再次确认, so that 已有授权不会被静默扩大。
21. As an 编辑器用户, I want 查看下载进度、取消下载并手动重试失败请求, so that 控制安装过程。
22. As an 编辑器用户, I want 实际包的摘要和清单与审核记录一致才安装, so that 附件被替换时不会接受未知内容。
23. As an 编辑器用户, I want 下载、准备或激活失败后保留旧版本与受管数据, so that 更新失败不破坏现有工作。
24. As an 编辑器用户, I want 市场安装继续遵守能力协商、工作区信任与权限规则, so that 上架不等于获得运行授权。
25. As an 编辑器用户, I want 保留本地 ZIP 导入, so that 可以使用独立获得的包。
26. As an 编辑器用户, I want 编辑器启动后和长时间运行期间自动检查更新, so that 不必先打开插件管理器。
27. As an 编辑器用户, I want 标题栏插件按钮在存在可用升级时显示红点, so that 注意到更新。
28. As an 编辑器用户, I want 查看管理器后红点仍保留直到不再有更新项, so that 未执行的升级不会被误标完成。
29. As an 编辑器用户, I want 自己触发插件更新, so that 后台检查不会自动改变安装版本。
30. As an 编辑器用户, I want 打开市场先显示缓存并在后台刷新, so that 可以及时浏览内容。
31. As an 编辑器用户, I want 手动刷新并看到缓存时间和失败状态, so that 知道列表是否已更新。
32. As an 编辑器用户, I want 列表刷新失败时禁用市场新装和升级, so that 不依据旧审核状态继续安装。
33. As an 编辑器用户, I want 刷新成功后重新判断版本与撤回状态, so that 可用操作正确恢复。
34. As an 编辑器用户, I want 首次无缓存且离线时看到明确空状态, so that 理解为什么市场没有内容。
35. As an 编辑器用户, I want 市场网络故障不影响已安装插件和本地导入, so that 仍能继续工作。
36. As an 编辑器用户, I want 附件失效或摘要错误时得到明确原因, so that 不会把无法下载误认为安装成功。
37. As an 编辑器用户, I want 已安装插件被下架时看到原因, so that 自己决定后续处理。
38. As an 编辑器用户, I want 下架不远程卸载或自动禁用已有插件, so that 保留对本机状态的控制。
39. As an 第三方作者, I want 提交自己的公开仓库、源码 commit、许可证和 Release 包地址, so that 无需迁移到官方仓库也可申请收录。
40. As an 第三方作者, I want 每个新版本经 PR 审核后上架, so that 发布路径明确且可追溯。
41. As an 插件维护者, I want 插件 ID 绑定登记维护者和来源仓库, so that 他人不能直接接管已有发布身份。
42. As an 插件维护者, I want 归属转移单独审核, so that 合法迁移保留连续身份。
43. As an 市场审核者, I want 同一 ID 和版本的包摘要不可覆盖, so that 修包必须产生新版本。
44. As an 市场审核者, I want 自动校验包格式和声明而不运行第三方插件, so that 审核流程保持明确边界。
45. As an 市场审核者, I want 说明正文、图标和更新日志随审核保存快照, so that 展示内容与收录记录一致。
46. As an 市场维护者, I want 通过 GitHub 托管目录、发布包与定时任务, so that 初版不维护额外后端和数据库。
47. As an 市场维护者, I want 下载统计只计算收录的插件包附件, so that 不把源码和校验文件算作插件下载。
48. As an 市场维护者, I want 撤回记录保留而默认搜索不再推荐撤回条目, so that 用户知道历史状态又不会继续新装。
49. As an 官方插件维护者, I want 每个正式插件有独立源码仓库和发布流程, so that 独立维护与升级。
50. As an 已有用户, I want 拆仓后保留插件 ID、设置和私有数据, so that 迁移不丢失使用状态。
51. As an Rust 用户, I want 市场仅提供合并后的 Rust 包, so that 使用统一的语言、Cargo 和调试能力。
52. As an 项目维护者, I want 先验证独立构建和安装再移除主仓库业务源码, so that 拆仓不会留下无法交付的插件。
53. As an 项目维护者, I want 删除示例源码前迁移依赖测试, so that 精简分发不降低公开能力的回归覆盖。
54. As an 新用户, I want 全新编辑器不随附插件且不主动推荐安装, so that 自己决定从市场取得哪些能力。
55. As an 项目维护者, I want 安装器、便携分发和双语说明一致反映无随附插件, so that 实际交付与说明一致。
56. As an Windows 用户, I want 完整流程经过真实原生交互验收, so that 编译成功之外的使用行为也可靠。
57. As an 其他平台用户, I want 不支持的平台版本不可安装且验证范围清楚, so that 不误以为所有平台都已验收。

## Implementation Decisions

### 职责与接口

- 扩展既有通用插件管理集成，管理目录获取、缓存、版本选择、下载与用户操作；继续通过后台工作队列和状态发布驱动原生界面。
- 复用运行时公开 Package 检查、Manager 安装和事务更新，以及 InstallControl 的进度与取消语义。市场负责候选来源和选择，不另建安装器、撤销栈或插件生命周期。
- 在官方注册表维护索引与版本记录，以静态数据契约连接审核发布和客户端消费；网页展示站点不在首版范围。
- 宿主按通用清单、能力和权限处理全部插件，不增加按官方插件 ID、语言或服务器名称分支，不为测试或拆仓增加插件专属 API。
- 控件沿用 gpui-base 行为与本地 UI 外观；相关文本进入中英文资源，保持键盘、输入法、主题、滚动与缩放行为。

### 注册表与分发契约

- 使用一个官方注册表接收第三方 PR。第三方地址指作者的公开 GitHub 仓库与 Release 附件，不指用户可添加绕过审核的市场源。
- 每个插件记录身份、维护者、来源仓库、主分类、标签及详情快照；每个版本记录包版本、发布时间、源码 commit、许可证、Release 附件、SHA-256、宿主与协议/能力要求、平台、权限、更新日志及撤回状态。
- 安装身份、包版本、协议版本和能力版本分别处理；继续保留现有官方插件 ID。
- 首次收录和每个版本都经过自动校验及人工审核。校验读取包而不执行访客代码，核对包与声明。公开源码、明确开源许可证和源码 commit 是收录条件；不宣称完整安全审计或已证明可复现构建。
- 维护者与仓库归属首次登记，后续核对申请身份；归属转移单独审核。同一 ID 和版本固定摘要，修包升版本。
- 作者托管实际包，官方市场不复制包。删除附件会影响下载，不承诺历史包永久可用。提交固定版本与摘要，不依赖 latest。
- 说明、图标、更新日志在收录时保存快照。编辑器按静态元数据展示详情，不为浏览预先下载所有包。
- 下载统计与目录准入状态分别表达；统计暂不可用不能被当成插件版本失效或阻止安装。

### 搜索、版本与安装行为

- 搜索名称、ID、简介、作者和标签，不搜索全文。一个主分类、多个标签，分类集合由注册表维护。
- 无搜索词默认下载次数排序，有搜索词默认相关性排序；另提供最近更新和名称排序。
- 详情提供已确认的全部身份、说明、许可、来源、兼容性、权限、版本、日志和统计信息；插件内容无译文时回退原文。
- 只收录稳定版。默认候选为当前宿主、所需能力及平台条件下可用的最高版本。显示所有收录的历史版本，对不兼容或撤回版本解释原因并禁用安装。
- 首次安装允许旧兼容版本；已有安装仅允许更高兼容版本，市场不提供同版本重装或降级。本地导入既有行为保留。
- 首装下载前确认声明权限；更新新增权限需确认。下载完成后重新核对摘要、实际清单和审核记录；不一致即拒绝，不能继承未确认权限。
- 下载有进度和取消，失败可手动重试，不做断点续传。只保留当前流程所需临时包，不承诺离线重装。
- 安装与升级遵守既有实例作用域、工作区信任、能力协商和数据事务。失败或取消保留旧版本；成功切换后按既有生命周期撤销旧资源。

### 刷新、红点与故障

- 启动后异步检查，长时间运行目标每 6 小时再检查。管理器先显示缓存，按新鲜度后台刷新，并提供手动刷新。
- 已安装插件存在更高、兼容且未撤回的可用版本时，标题栏插件按钮显示红点。查看不消除；更新后或不再有可更新项时消除。
- 更新检查不自动下载安装；网络失败保留最后有效结果并标明时间与错误。
- 索引刷新失败只允许浏览缓存，禁止发起市场新装或升级，提示“无法刷新插件列表，请稍后重试”。成功刷新后重新判断版本与撤回状态，再恢复可用操作。
- 首次无缓存且联网失败时显示空市场；无随附包兜底。已安装插件、本地导入和不依赖插件的内置能力继续可用。
- 附件失效或摘要错误阻止该包安装；撤回条目从默认搜索移除，历史与已安装页面保留原因。下架不远程卸载或自动禁用。
- 统计目标每 6 小时刷新，非严格准时承诺。累计和版本次数仅汇总插件包附件，包含重复与外部下载，不代表安装人数。失败保留旧值及时间，无历史值时显示暂不可用。
- 客户端只知道已获取的目录状态，不承诺立即获知撤回；缓存与迟到请求不能覆盖较新的有效状态。

### 拆仓与交付顺序

七个正式插件为 HTML、JavaScript、Markdown、Rust、Image、TOML、XML。Rust 合并是外部依赖，只上架合并后的 Rust，不另行发布 Rust Debugger。以该任务实际验收为准，不重复实现或继承未经核实的完成声明。

各插件独立仓库成为唯一业务源码来源，通过公开宿主 SDK 构建，不添加主仓库内部依赖或 SDK 源码副本。验证后移除主仓库实现；移除示例源码前迁移专用测试夹具，保留原有验证能力。旧用户安装记录和私有数据不随源码移除而删除。

以下是六个实施阶段与完成条件；已获批准的四张端到端工单将相关阶段合并交付，尚未开始执行：

| 阶段 | 交付内容 | 前置与完成条件 |
| --- | --- | --- |
| 1. 注册表与准入 | 静态记录契约、第三方 PR 校验、人工审核规则、快照生成、Pages 数据发布与统计 | 先登记实际注册表仓库和发布地址；受控候选可生成客户端可读目录，无效身份、包或同版本替换被拒绝 |
| 2. 在线安装闭环 | 目录读取、缓存、原生列表与详情、权限确认、下载校验、既有 Manager 安装 | 使用阶段 1 目录完成真实有效 ZIP 的首次安装；刷新失败阻止新装，网络与取消错误不损坏已有状态 |
| 3. 版本与更新 | 搜索分类排序、历史版本、更新日志、最高兼容版本、启动与周期检查、红点及撤回处理 | 基于阶段 2 完成升级、拒绝降级/重装、不兼容拒绝、统计失败和撤回场景 |
| 4. 官方插件独立发布 | 七个独立仓库、公开 SDK 独立构建、固定版本 Release、审核收录 | Rust 项目先完成合并验收；所有正式包均可从市场路径取得并安装，保留身份和行为 |
| 5. 发行与测试迁移 | 测试转专用夹具、移除示例及迁出源码、取消随附包、清理随附推荐、更新发行说明 | 先验证替代测试及独立包，再移除原源码和随附依赖；全新安装及旧用户升级保持已确认行为 |
| 6. Windows 终验 | 全流程、故障、真实 UI、安装器与便携分发验收 | 所有验收项有实际结果，未执行项明确记录，完成前不宣称交付 |

阶段 2 可用隔离夹具贯通，不等待七个官方仓库全部迁完；阶段 5 不能在阶段 4 的真实包和替代测试未验证前删除依赖。阶段顺序不自动授权并行代理或发布版本。

## Testing Decisions

### 已确认的主要测试接缝

采用一条主要端到端测试流程：

**受控静态目录与实际 ZIP → 插件管理器的市场操作 → 实际下载及 Package 校验 → 公开 Manager / InstallControl → 后台状态发布 → 原生界面和安装结果。**

复用现有高层安装与事务接缝。联网层使用本地 HTTP 夹具提供目录和 ZIP，模拟失败、取消、附件变化及撤回；生产客户端继续只接受审核通过的官方目录，测试夹具不变成用户可配置的未审核市场源。测试路径必须实际经过目录、下载、校验及 Manager，不直接填充成功状态替代在线安装测试。

仅在新市场来源接入层集中提供可替换的目录/下载来源；若现有传输入口可复用则复用，不为每个低层步骤新增测试接口。调度使用可控测试时间验证六小时触发，不让测试真实等待六小时。注册表的外部输出直接作为客户端输入，避免两边各造不一致的假契约。

### 先例与验证原则

- 参考现有插件管理 GPUI 测试：生成真实声明式 ZIP，通过公开 Manager 安装，再用真实指针/键盘事件验证详情控件和用户可见状态。
- 参考受管依赖及宿主依赖安装测试：本地 HTTP 传输、摘要校验、权限确认、取消与原生状态发布。
- 参考既有事务更新、数据迁移、作用域及恢复测试：以旧版本行为和私有数据是否保留判断结果，不断言内部容器或辅助函数。
- 示例源码移除后，上述先例依赖的组件改为专用夹具或固定版本正式包；先前 ignored 用例不得通过删除或继续跳过被计为验证成功。
- 声明式资源与含 WASM 行为两类包均覆盖。兼容筛选、排序等纯规则可补小范围输入输出测试，但不能替代实际安装链路。
- 注册表自动校验只检查第三方包，不执行它；测试运行受控自有夹具是另一条明确隔离的验证流程。
- 自动化测试使用隔离数据目录与本地服务，不操作真实用户安装。GitHub 实际发布链路及 Windows 原生交互在交付验收中验证。

### 验收矩阵

| 编号 | 场景与可观察结果 |
| --- | --- |
| M01 | 第三方首次及新版本 PR 经校验与人工审核后进入索引；单独发布 Release 不自动上架 |
| M02 | 未登记维护者、错误来源、缺少开源许可或源码定位被拒绝；归属转移走单独审核 |
| M03 | 同 ID 同版本不同摘要无法覆盖；目录声明与实际包不符、包格式非法不能收录或安装 |
| M04 | 静态目录包含详情、版本、权限、兼容及撤回信息；客户端可直接消费，浏览不下载完整包 |
| M05 | 五个搜索字段、分类和四类排序符合规则；无结果状态可理解 |
| M06 | 全新安装无随附包；无缓存离线显示空市场和失败原因，纯文本与内置能力仍可用 |
| M07 | 首次确认权限后从受控源下载并安装实际 ZIP；拒绝授权不会安装或运行 |
| M08 | 同时有多个版本时默认最高兼容稳定版；首装可选旧兼容版，不兼容和撤回版本解释原因并禁止 |
| M09 | 市场对已有版本只提供升级，不提供降级或同版本重装；本地导入行为继续可用 |
| M10 | 新增权限更新再次确认，拒绝后旧版本可用；权限不变不反复授权 |
| M11 | 下载进度可见、取消有效、失败可手动重试；旧版本及数据不受影响 |
| M12 | 实际包被替换、SHA-256 错误或权限与索引不符时拒绝安装 |
| M13 | 列表刷新失败即使 ZIP 可下载也禁止发起市场安装/升级；成功刷新后按当前状态恢复操作 |
| M14 | 缓存先显示并标明时间；失败保留最后有效数据；迟到结果不覆盖新状态 |
| M15 | 启动、六小时调度及手动刷新触发检查；不自动下载安装 |
| M16 | 可用升级使标题栏插件按钮显示红点；仅查看不清除，更新完成或无可更新项时清除 |
| M17 | 累计及版本统计只汇总目标附件；包含重复/外部下载的口径明确；统计失败不清零也不单独阻止安装 |
| M18 | 失效附件有明确失败；撤回记录保留，刷新后不能新装，已安装页可看原因且不自动卸载禁用 |
| M19 | 受限工作区、作用域、能力协商及资源归属继续生效；市场收录不授予权限 |
| M20 | 更新准备、迁移或激活失败，旧实例与受管数据恢复；成功切换撤销旧资源 |
| M21 | 七个正式插件用公开 SDK 独立构建，通过市场路径安装且 ID/设置/私有数据连续；仅上架合并 Rust |
| M22 | 示例源码移除，依赖测试迁至专用夹具且行为覆盖保留；不自动清理用户已装示例或其数据 |
| M23 | 安装器和便携包不含随附插件依赖，不再主动推荐；旧用户既有安装可管理 |
| M24 | 中英文、深浅主题、键盘焦点、中文输入、滚动、缩放、版本和更新日志入口通过原生交互验收 |
| M25 | 包含实际 WASM 的权限、事务和生命周期场景执行成功；未执行 ignored 用例单独披露 |
| M26 | Pages 目录、真实 Release 下载及统计流程完成部署验收；远程制品版本/摘要与索引一致 |

每个实现阶段先跑受影响模块的针对性测试；涉及宿主 Rust 的交付在 Nanobug 宿主仓库执行 cargo fmt --check、cargo test --workspace --exclude editor-app、cargo check --workspace。市场仓库使用实际新增技术栈的格式、契约、发布与集成检查；纯市场变更不重复无关宿主构建。修改原生应用追加对应 GPUI 测试和原生交互；真实 WASM 夹具先用当前 Cargo/宿主公开构建入口准备，再显式运行 ignored 用例。沿用现行工具链，不调用已退役脚本或自动安装工具链。

Windows 是完整行为验收平台；索引支持操作系统与架构声明，不支持当前平台的版本不能安装。其他平台保留既有构建要求，未实测不宣称通过。本次文档整理只检查结构、链接和差异，不将任何计划测试标为已通过。

## Out of Scope

- 独立市场网站、额外服务端或数据库、私有 GitHub 插件、用户绕过审核添加市场源。
- 评分、评价、付费、推荐广告、个性化推荐、说明全文搜索和预发布版。
- 静默更新、主动缺失语言推荐、市场降级和同版本重装。
- 断点续传、离线包仓库、包镜像、历史附件永久可用保证。
- 安装人数、去重用户统计、精确实时下载量和准点调度保证。
- 收录即安全认证、远程卸载或自动禁用、立即获知所有撤回。
- 重新实施 Rust 合并、扩大宿主产品能力或为官方插件增加专属 API。
- 本次规格整理不执行生产代码、源码迁移、示例删除、远程插件仓库创建、Release 发布、提交推送或关闭既有议题。
