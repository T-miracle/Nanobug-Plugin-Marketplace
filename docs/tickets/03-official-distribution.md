# 03：七个官方插件独立构建、发布与市场安装

状态：拆分及阻塞关系已获用户批准，待发布本仓库；尚未实施。稳定标识：`plugin-marketplace-v1-03`。

## Parent

[执行规格](../specs/plugin-marketplace.md)（本仓库议题待发布；原 Nanobug #100 仅作历史参考）。

## What to build

将 HTML、JavaScript、Markdown、合并后的 Rust、Image、TOML、XML 迁至各自独立仓库，成为正式维护来源。每个仓库可使用公开 SDK 独立构建、发布固定 ZIP、通过注册表审核，并由编辑器真实下载和安装。该单一次覆盖七个插件，避免按仓库拆成重复的构建发布工单。

## Acceptance criteria

- [ ] 登记七个实际独立仓库的归属与名称，保留现有插件 ID。独立源码使用公开宿主 SDK 构建，不依赖主仓库内部路径，不附带 SDK 源码副本。
- [ ] Rust 合并属于外部准入条件：先读回实际合并验收和包版本，仅迁移、上架合并 Rust；不重新实施合并，也不发布独立 Rust Debugger。
- [ ] 各包通过现行正式构建和打包入口产生 ZIP，记录源码 commit、包版本、SDK/能力要求及 SHA-256。实际修改并交付包资源时按约定升版本。
- [ ] 每个正式包经过同一注册表审核，发布在其作者仓库的 Releases；索引、包和源码对应，真实 Pages 与 Release 路径可用。
- [ ] 七个包均能从原生市场下载和首次安装，并各验证一个代表性用户行为；语言插件验证识别/高亮及适用语言服务，Markdown 验证其编辑/显示能力，Image 验证图片显示，Rust 验证语言/Cargo/调试组合的必要烟测。
- [ ] 保留已有安装身份、设置、私有数据和作用域；本单不自动修改真实用户状态。完整市场升级矩阵由 02 负责，本单验证候选身份连续性，组合旧用户升级由 04 验收。
- [ ] 独立仓库成为业务修改的权威位置；主仓库原实现暂作冻结的过渡构建/测试输入，不双份维护。待 04 的替代测试准备完毕再整体移除。
- [ ] 实际部署核验包括 Pages 目录、Release 下载、版本摘要与客户端消费；统计任务本体由 02 主责，04 组合验证真实官方附件能进入统计。
- [ ] 记录每个包的独立构建和代表行为证据；不得用一个成功包替代七个包的实际安装与必要行为验证。

## Testing and evidence

主责验收：M21、M26。
主责用户故事：49、50、51、52。

复用统一的独立 SDK 构建、ZIP 检查和市场安装场景，对七个包参数化执行；每个包有真实安装和自身代表行为证据，不把平台权限/网络完整负面矩阵重复七遍。构建产物按完整输入指纹复用，每个运行场景使用隔离数据目录。迁移不改变业务行为时复用既有完整业务验收并附差异分析；源码、资源、SDK 或平台依赖变化则重跑受影响业务测试。涉及真实 WASM/原生服务的场景显式准备并执行，构建缺失不伪报通过。宿主未变化时不为每个仓库重复宿主全量构建；本单最终交付仍执行共同门禁。

共同交付门禁：先完成受影响模块针对性测试；涉及宿主 Rust 时，在宿主仓库执行 cargo fmt --check、cargo test --workspace --exclude editor-app、cargo check --workspace。市场仓库运行实际技术栈的格式、契约与集成检查；纯文档验证路径、编号和差异，不执行无关 Rust 构建。涉及原生应用追加相关应用测试及真实交互；实际 WASM 先准备夹具再显式执行 ignored 场景。保持各步骤可编译，必要预重构先保行为验证。记录提交/工作树、包摘要、SDK/工具链、实际命令、结果和未验证限制；未验收不关闭。

## Boundaries

不开始删除主仓库实现或示例，不提前取消随附发行；不等待 02 的全部增强功能即可基于 01 验证首次安装。不将 Rust 合并的其他任务成果计为本单实现。
