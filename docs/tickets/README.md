## 预重构和迁移顺序

- 未发现必须单列广域重构工单的证据。每单如需局部抽取，第一步先保持行为并验证，再接新增行为。
- 官方拆仓按扩展—收缩：03 建立并验证独立正式来源，过渡期冻结主仓库原实现；04 先迁测试，再删除旧输入和示例。各单可绿色交付，不让源码删除先于可用替代。
- 七个插件不拆成七张结构重复的迁移单；03 共用流程但保留每包独立构建、安装和代表行为证据。不顺带修改各插件业务设计。
- 01/02 使用受控声明式和 WASM 夹具完成真实链路，不依赖七个正式仓库先迁完。04 不能成为补做前单权限、故障和原生测试的兜底单。

## 测试质量与减少重复

1. **一项验收一个主责工单。** 下表给 M01–M26 各指定唯一主责。主责完成完整自动化断言与必要手测；后单只新增自身行为和跨边界回归，不复制同一套负面矩阵。
2. **共用一条高层流程。** 注册表产物/实际 ZIP → 市场操作 → 下载与 Package → 公开 Manager/InstallControl → 状态发布和原生结果。复用 01 的本地 HTTP 夹具、隔离安装环境及可控时钟，不按插件新增宿主测试接口。
3. **开发时先跑针对性测试。** 在变更收敛后每单执行一次规定的完整交付门禁。若形成新的实现交付阶段或门禁后修改代码，仍需按仓库约定验证该阶段；不能用改名阶段跳过检查。
4. **按实际修改仓库保留交付门禁。** 涉及宿主 Rust 时，在宿主仓库执行 cargo fmt --check、cargo test --workspace --exclude editor-app、cargo check --workspace；应用 UI 和实际 WASM ignored 测试另外执行。市场仓库运行所选技术栈的格式、契约和集成检查；纯文档检查链接、编号和差异，不重复无关 Rust 构建。四个完整工单减少无意义的反复全量检查，不把全部验证拖到最后。
5. **复用制品，不复用脏状态。** 源码、SDK、锁文件、清单、资源、工具链、目标和参数输入完全相同才复用校验过的包；任一输入变化则重建受影响包。每个场景用独立用户数据与授权状态。
6. **按行为影响选择回归。** 目录/传输/准入变化重跑 01 相关失败矩阵；版本/权限/事务变化重跑 02 对应场景；SDK/资源变动重跑受影响正式包；UI 基座变化补对应输入与焦点验证；删除/迁移重跑实际依赖消费者。
7. **旧证据不冒充新版本通过。** 引用前单记录需注明基线、包摘要与差异分析。相关调用链变化、出现失败或仍有疑点时必须重跑；完全无变化且检查已通过时，不因写文档或等发布再次全测。
8. **七包按差异验收。** 03 每包都构建/安装并验证代表能力，但网络/权限/版本通用矩阵不手工重复七遍；宿主未变化时不为每次插件上传重复全 workspace。
9. **最终只做一次短组合。** 04 在最终安装器/便携环境从无插件走到市场安装、能力使用、发现更新、升级、目录故障和撤回提示；完整边界自动测试按影响重跑，不再次全量人工逐项重演。
10. **记录实际结果。** 每单交付记录包含提交或工作树、包摘要、工具链、命令、结果及跳过原因；未执行 ignored 用例不计通过。Windows 完整验收，其他平台准确披露限制。
